## 一、第一周的最终目标

第一周不做完整剧情、不做正式美术、不做复杂怪物 AI。唯一目标是证明以下核心循环能够运行：

> 第一人称探索 → 与场景交互 → 进入安全室查看监控 → 判断怪物位置 → 离开安全室完成任务 → 返回安全室获得反馈

第一周结束时，应该得到：

- 一个可运行的 UE 5.8 第一人称项目。
- 图书馆五个区域的灰盒地图。
- 玩家移动、手电、射线交互和开门功能。
- 一个安全室和五路基础监控。
- 一个简单但完整的找保险丝任务。
- 一个夜班馆员的节点巡逻原型。
- 老周和林秋的基础 NPC 占位与对话。
- 一个躲藏点。
- 一个可以打包运行的 Windows 版本。
- 一份 Git 提交和 60—90 秒原型视频。

第一周结束时，不要求画面完整，也不要求既有剧情全部实现。

## 三、每天的固定节奏

建议每天按照以下时间结构执行：

| 时间 | 内容 |
|---|---|
| 20—30 分钟 | 只学习当天需要的 UE 功能 |
| 90—150 分钟 | 在项目中实现功能 |
| 30—60 分钟 | 调试、打包或测试 |
| 10—15 分钟 | 更新开发日志并提交 Git |

学习原则：

1. 只学习当前任务需要的功能。
2. 教程中的案例必须在当天项目中复现。
3. 不追求一次做对，先实现最小可运行版本。
4. 每天结束时必须保留一个能打开的项目版本。
5. 不允许出现无法解释的 AI 或教程复制代码。

## 五、第二天：第一人称交互系统

### 学习目标

- Enhanced Input。
- 摄像机朝向的 Line Trace。
- Blueprint Interface。
- Actor 自定义事件。
- 交互提示 UI 的最简单实现。

### 要创建的蓝图

```text
BP_NL_PlayerCharacter
BPI_Interactable
BP_InteractTest
BP_Door
```

命名前缀含义：

| 前缀 | 含义 |
|---|---|
| BP_ | Blueprint Actor |
| BPI_ | Blueprint Interface |
| WBP_ | Widget Blueprint |
| E_ | Enum |
| DA_ | Data Asset |
| L_ | Level |

### 交互逻辑

玩家从第一人称摄像机中心向前发射射线。

建议参数：

```text
检测距离：250 cm
检测频道：Visibility
命中后检测目标是否实现 BPI_Interactable
```

`BPI_Interactable` 至少包含：

```text
CanInteract
Interact
GetInteractionText
```

交互显示逻辑：

1. 射线命中可交互物时，HUD 显示“按 E 交互”。
2. 没有命中时，提示隐藏。
3. 按下 E 时调用目标的 `Interact`。
4. 交互结束后重新检查目标是否仍然有效。

### 门的功能

`BP_Door` 第一版只需要：

- 初始关闭。
- 按 E 打开。
- 再按 E 关闭。
- 打开和关闭时播放占位音效。
- 门旋转使用 Timeline 或简单插值，不要一开始做复杂动画。

### 手电筒

给角色添加一个 Spot Light 组件。

控制方式：

```text
F：开关手电筒
```

手电筒不需要耗电，第一周只验证开关和照明效果。

### 当天验收

- 玩家看向测试物体时显示交互提示。
- 按 E 可以改变测试物体状态。
- 门可以打开和关闭。
- 按 F 可以开关手电筒。
- 不通过 Cast 到具体角色实现所有交互，优先使用 Interface。

## 六、第三天：五个区域的灰盒地图

### 学习目标

- Blockout 和关卡比例。
- 关卡照明与玩家动线。
- Trigger Volume。
- Actor Tag 和关卡中对象的管理。
- 如何让玩家在不看地图的情况下理解空间。

### 五个区域

在 `L_Prototype` 中用简单方块搭建：

1. 门厅与总值班台。
2. 阅览区。
3. 主书库。
4. 旧目录室。
5. 档案修复室。

建议尺寸仅用于灰盒：

| 区域 | 建议尺寸 | 主要用途 |
|---|---|---|
| 门厅与安全室 | 8m × 6m | 开始、监控、最终离开 |
| 阅览区 | 18m × 12m | 桌椅、躲藏、林秋线索 |
| 主书库 | 22m × 16m | 保险丝、书架迷宫、追逐 |
| 旧目录室 | 10m × 8m | 档案卡、林秋、调查 |
| 档案修复室 | 10m × 6m | N-00 胸签、最终任务 |

### 动线要求

1. 五个区域必须连通。
2. 地图必须有两条路线：
   - 主路线：门厅 → 阅览区 → 书库 → 目录室 → 档案室。
   - 绕行路线：档案室 → 服务走廊 → 书库 → 门厅。
3. 书库的书架不能把玩家完全堵死。
4. 阅览区至少有六个桌子可以作为躲藏点。
5. 安全室放在门厅后方，不要太深。
6. 每个房间至少有两个出口，最后一个房间除外。

### 建议创建

```text
BP_ZoneVolume
BP_LockdownTrigger
BP_LightController
```

`BP_ZoneVolume` 用于：

- 记录玩家当前所在区域。
- 让怪物选择房间节点。
- 给 HUD 显示房间名称。

`BP_LockdownTrigger` 第一版只需要：

- 玩家进入门厅触发区后关闭主门。
- 主门灯光变红。
- 广播播放一句占位音频。

### 当天验收

- 可以连续走完五个区域。
- 玩家不会卡在角落或书架中。
- 可以从两条不同路线从安全室走到档案室。
- 触发封锁后主门有视觉效果。
- 地图保存为 `L_Prototype`。
- 当天提交：

```powershell
git add .
git commit -m "feat: add five-zone library blockout"
git push
```

## 七、第四天：安全室和五路监控

### 学习目标

- Scene Capture Component 2D。

- Material 或 Widget 的图像显示。
- Widget Blueprint。
- UMG 输入模式。
- 如何在监控模式和玩家移动模式之间切换。

### 要创建


### 摄像头布置

在五个区域各放置一个 `BP_CCTV_Camera`：

```text
CCTV_01_Entrance
CCTV_02_Reading
CCTV_03_Stacks
CCTV_04_Catalog
CCTV_05_Archive
```

每个摄像头包含：

- Scene Capture Component 2D。
- Render Target。
- 唯一摄像头编号。

第一版使用较低分辨率：

```text
640 × 360
```

五个摄像头不要同时高频捕获。玩家当前查看哪一个，就启用哪一个。

### 监控终端逻辑

1. 玩家进入安全室。
2. 靠近终端后按 E。
3. 切换到 `WBP_CameraMonitor`。
4. 按数字键 1—5 切换画面。
5. 按 Escape 退出。
6. 进入监控时禁止玩家移动和转动。
7. 退出监控时恢复角色输入。

输入模式建议：

```text
进入监控：Set Input Mode Game and UI
退出监控：Set Input Mode Game Only
角色输入：进入监控时禁用移动，退出时恢复
```

### 监控 UI 内容

- 当前摄像头编号。
- 当前区域名称。
- 画面窗口。
- 当前备用电力。
- 退出提示。

不要在第一天制作漂亮边框。先确认实时画面能显示。

### 当天验收

- 五路监控都能显示正确区域。
- 切换摄像头不会出现黑屏。
- 进入监控后角色不会继续移动。
- Escape 可以退出。
- 退出后可以正常走动和交互。

## 九、第六天：夜班馆员节点巡逻

### 学习目标

- Timer 和延迟节点。
- Enum。
- Array 和相邻节点。
- Actor 距离判断。
- 简单的状态切换。
- 不学习完整 Behavior Tree。

### 要创建

```text
BP_MonsterRoomNode
BP_NightLibrarian
E_MonsterState
BP_NoiseReporter
```

### 房间节点

在关卡中放置六个节点：

```text
Node_Entrance
Node_Reading
Node_StacksA
Node_StacksB
Node_Catalog
Node_Archive
```

每个 `BP_MonsterRoomNode` 包含：

- 房间名称。
- 相邻节点数组。
- 摄像头编号。
- 是否允许怪物停留。
- 安全室距离。

### 怪物状态

第一版只实现：

```text
Patrol
Search
Hunt
```

### Patrol

- 每隔 20—30 秒选择一个相邻节点。
- 只有在当前节点未被玩家持续观察时才移动。
- 移动时给摄像头发送画面干扰事件。
- 不要求真实走路动画。
- 第一版可以使用 `SetActorLocation` 进行节点切换。

### Search

- 玩家制造噪音后，把噪音位置传给怪物。
- 怪物选择最接近噪音的节点。
- 搜索持续 10—15 秒。
- 搜索结束后返回 Patrol。

### Hunt

第一版只做基础追逐：

- 玩家距离小于 500 cm 且处于视线锥体内时进入 Hunt。
- 怪物向玩家移动 5—8 秒。
- 玩家离开视线并保持 5 秒后结束追逐。
- 暂时不做复杂攻击动作。

### 简单噪音来源

以下操作调用 `BP_NoiseReporter`：

- 奔跑。
- 扔下书本。
- 开关门。
- 操作配电柜。

### 当天验收

- 怪物会从当前房间移动到相邻房间。
- 监控中可以看到怪物换房间。
- 怪物不会连续跨越三个房间。
- 玩家进入同一房间时会触发搜索或追逐提示。
- 追逐结束后怪物能返回巡逻。

- 不要制作复杂怪物动画。
- 不要实现多个怪物。
- 不要使用 Behavior Tree 制作完整 AI。
- 不要开始 Blender 建模。
- 不要制作正式 UI 皮肤。
- 不要制作片头、片尾和完整结局动画。
- 不要加入枪械、射击或近战。
- 不要为了实现完整剧情而暂停核心循环开发。
- 不要把所有资产都放在一个文件夹里。

## 十四、常见问题与排查

### 交互没有反应

检查：

- Line Trace 是否使用正确频道。
- 目标是否实现 `BPI_Interactable`。
- 摄像机是否朝向正确。
- 交互距离是否太短。
- UI 是否被其他控件遮挡。

### 监控黑屏

检查：

- Scene Capture Component 2D 是否启用。
- Render Target 是否创建。
- 材质或 Widget 是否使用了正确 Render Target。
- 摄像头是否被墙体遮挡。
- 是否同一时间启用了太多摄像头。

### 进入监控后角色还能移动

检查：

- 是否调用 Set Input Mode UI Only 或 Game and UI。
- 是否禁用角色移动输入。
- 是否恢复旧的输入状态。

### 怪物穿墙

第一周使用节点移动，不要让怪物直接 `MoveTo` 玩家世界坐标。怪物应该先选择 `BP_MonsterRoomNode`，再从节点到节点。

### Git LFS 文件异常

```powershell
git lfs status
git lfs ls-files | Select-Object -First 20
```

如果 `.uasset` 文件没有经过 LFS，需要检查 `.gitattributes`。

## 十六、第一周结束后的标准

第一周结束时，不需要满足完整考题，但必须满足以下条件：

> 我可以从安全室看监控，判断怪物位置，离开安全室完成任务，被怪物追赶，躲起来，然后安全返回。

如果这个循环不成立，第二周不要开始正式美术和剧情扩展。

如果这个循环成立，第二周再开始实现：

- 规则手册完整页面。
- 安全室门锁和电力消耗。
- 监控中的怪物追踪。
- 更完整的追逐和搜索状态。
- 老周、林秋的正式互动。
- 档案室和 N-00 的故事流程。
